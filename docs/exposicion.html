Backend09

Control de acceso por rol, escrito una sola vez

usuarios/permisos.py
def rol_requerido(*roles):
  def decorador(view_func):
    @login_required
    def wrapper(request, *a, **kw):
      if request.user.rol not in roles:
        raise PermissionDenied   # 403
      return view_func(request, *a, **kw)
    return wrapper
  return decorador

class RolRequeridoMixin(LoginRequiredMixin,
                        UserPassesTestMixin):
  def test_func(self):
    return self.request.user.rol in \
           self.roles_permitidos
Uso en una vista
class ListaPagosResidente(
        RolRequeridoMixin, ListView):
  roles_permitidos = ('residente',)

  def get_queryset(self):
    return Pago.objects.filter(
      id_residente_fk__usuario=
        self.request.user)
  • Decorador para vistas función, mixin para vistas clase.
  • Además del rol, cada residente solo ve sus propios registros.

  1. El admin guarda el residenteCrearResidente.form_valid()
  2. Si ya existe un usuario con ese email, se vinculasin email: se guarda y se avisa que no hay cuenta
  3. Si no, se crea el usuario a partir del emaillaura, y si ya existe, laura1, laura2…
  4. Contraseña temporal aleatoria de 8 caracteresget_random_string(8) + create_user() la guarda cifrada
  5. Se marca debe_cambiar_password = Trueel middleware lo envía a «Cambiar contraseña»
  6. Al cambiarla, la bandera vuelve a FalseCambiarPasswordView.form_valid()
usuarios/middleware.py
class ForzarCambioPasswordMiddleware:
  def __call__(self, request):
    u = request.user
    if (u.is_authenticated
        and u.debe_cambiar_password
        and ruta not in PERMITIDAS):
      return redirect('cambiar_password')
    return self.get_response(request)
